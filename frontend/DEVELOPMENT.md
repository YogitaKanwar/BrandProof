# Local frontend

Use Node 24. From frontend/: npm.cmd run dev; npm.cmd run build; npm.cmd run lint; npm.cmd test.

Current contract is PR #1 (cdda60fd), not the earlier foundation. See ../docs/integration-sprint.md for exact setup/routes and ../docs/configured-backend-tests.md for unfinished runtime acceptance.

Start the backend on :8000 and Vite on :5173. New Review connects the demo -> campaign/publication date -> typed fact/explicit owner confirmation -> save caption and/or Upload poster -> Run Review -> findings/comments/corrections -> creator request -> reviewer decision -> receipt. All stages stay in one review workspace. Demo roles are synthetic, not production identity.

Unsaved workspace edits warn before navigation, Back or reload; cancel keeps the editor open. Selected images block review until uploaded or removed. Only acknowledged caption saves advance a pending upload's revision; real concurrent writes still require explicit reconciliation. Sticky stage links and the results' Human Review link avoid scrolling through the whole page. Dashboard readiness comes from actual receipts; automated findings do not imply approval.

Role tokens stay in JS memory. A 24-hour HttpOnly, SameSite=Strict cookie restores the same workspace through POST /api/v1/demo-sessions/resume with X-BrandProof-Session: resume. Startup calls resume without creating a sandbox; 401 means no restorable session, while network/403/5xx failures remain errors with Retry. Unsaved edits are not restored. A new demo is explicit and creates a separate workspace; explicit local drafts remain separate. Never store role tokens in localStorage/sessionStorage/URLs. Guidelines remain unparsed local context. Source versions are generated by the server. Poster uploads use raw bytes, private canonical retrieval and actual OCR status. No poster-delete route is assumed.

AI consent begins unchecked and resets after each run. Only caption/selected approved text is sent to the server-configured provider after explicit consent plus server enablement. Never put provider keys in VITE_ variables. Incomplete coverage requires actual reviewer notes; no notes are prefilled and no approval is automatic.

Copy .env.example to an ignored .env.local for API locations only. VITE_API_BASE_URL defaults to /api/v1; BRANDPROOF_API_TARGET controls dev/preview proxy. On the backend, BRANDPROOF_DEMO_COOKIE_SECURE=false is an explicit local HTTP override; production defaults to Secure cookies. Use the same public origin for frontend and /api so Strict cookies can restore the workspace. Credentialed CORS requires exact origins. Production needs an actual HTTPS API/reverse proxy, durable storage and approved deployment.

Checks with running local backend: npm.cmd run test:api, test:sources, test:reviews, test:posters, test:collaboration, test:approval, test:consent. Fixtures and scripted reviewer notes are fictional test data, not user feedback. No tokens logged.

Run npm.cmd run verify for a fail-fast build/lint/unit/HTTP pass. Set BRANDPROOF_RUN_BROWSER=1 and BRANDPROOF_TEST_BACKEND=1 to include the documented browser environment too. Latest broad results and user entry-path fixes: ../docs/regression-report.md. New Review is connected by default; local-only drafts use #/local-new explicitly.

Browser: start preview on :4173 plus dedicated headless Chrome CDP :9223. Set BRANDPROOF_TEST_BACKEND=1 and run npm.cmd run test:browser. Optional BRANDPROOF_TEST_URL targets :5173. The test clears only its dedicated profile's origin storage. BRANDPROOF_SCREENSHOTS=1 saves ignored screenshots under node_modules/.cache/brandproof-screenshots.

No frontend dependencies added. Existing starter/previous components are retained; the app mounts one current workspace. Backend files are unchanged beyond merging PR #1. No deployment or main-branch merge authorised.
