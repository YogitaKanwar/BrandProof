## Issues and reproduction steps

### QA-01 — P1: OCR misses a prominent price but extraction is labelled completed

1. Confirm price INR 499 in a campaign.
2. Upload `outputs/BrandProof_Final_Demo_Kit/06-ocr-limitation-poster.png` from the projectless workspace listed under Fixtures below. It visibly contains `INR 599` in large text.
3. Run review and open OCR text / poster rule coverage.

Actual OCR: `Workshop Terms apply Synthetic test artwork - not a real event`. The price is absent. The extraction status is `completed`, the OCR details say `No extraction warning`, and the price rule is `not_assessed`.

The engine correctly avoids a false pass, but the important price is not detected and the extraction wording can reassure a hurried reviewer. The failure exists even with a high-contrast synthetic poster. `backend/brandproof/ocr.py:17` uses one fixed PSM 6 layout.

Suggested work: evaluate bounded alternate segmentation for sparse/mixed-size layouts; retain provenance and deduplicate actual extracted words. Make the UI explicit that OCR completion only describes returned extraction, not complete reading. Do not hard-code this fixture, invent missing text or turn unassessed checks into passes. Measure misses and false positives on a small frozen poster set before claiming improvement.

Acceptance: this fixture either extracts the price with genuine coordinates or clearly requires manual inspection. Other supported posters must not regress; no fabricated boxes or coverage.

### QA-02 — P2: Flattening OCR lines weakens price classification

1. Use only confirmed INR 499 as the price reference.
2. Upload `04-wrong-price-poster.png` and run review.

OCR reads `Fictional workshop Book for INR 599 Terms apply Synthetic demo, not a real event`. The price is found and has coordinates, but the result is `Needs clarification` because the surrounding joined text is outside the supported main-value grammar. In contrast, `work/manual-qa-fixtures/price.jpg`, containing `Book for INR 599.`, produces a supported contradiction.

`backend/brandproof/ocr.py:112` concatenates words with spaces and discards line boundaries. Investigate preserving TSV block/paragraph/line structure with correctly recalculated text offsets. Keep the conservative scope rules: a genuine secondary/conditional price must still abstain.

Acceptance: test a simple multi-line main-price poster, an ambiguous secondary price and exact coordinate readback. Correct the accompanying demo claims too: the current multiline PNG demonstrated a clarification, not a definite contradiction. A JSON assertion that only counts category `price` is insufficient to distinguish them.

### QA-03 — P2: Workflow timestamps display UTC as browser-local time

The corrected example review displays `10/28/2026, 4:25:29 PM`, while its subsequently posted comment displays `10/28/2026, 10:55:36 AM` in the same browser. This is a 5h30 timezone inconsistency in the audit trail.

`backend/brandproof/review_schemas.py` normalises review timestamps to UTC-aware datetimes; the datetime fields in `backend/brandproof/workflow_schemas.py` do not use that normalisation. SQLite can return naive values. `frontend/src/Collaboration.tsx` parses both through `new Date(...).toLocaleString()`.

Suggested work: consistently return timezone-aware UTC ISO timestamps for workflow records and revisions. Verify a comment posted after a review is displayed after it in Asia/Kolkata and UTC. Inspect approvals/requests/decisions too rather than fixing only the one visible comment.

### QA-04 — P2: An existing caption cannot be removed to review only the saved poster

1. Use a campaign with a saved caption and an uploaded poster.
2. Clear the caption field.

Both Save caption and Run review become disabled. No explicit remove-caption action is exposed. The user can restore the old text, but cannot change this existing campaign to poster-only using the tested UI. `frontend/src/LiveCaption.tsx:108` blocks empty saves.

Suggested work: decide and implement an explicit revision-checked clear-caption operation, preserving the saved poster and invalidating the previous review. Backend contract work may be required. Keep the guard against reviewing a campaign with neither caption nor poster.

Acceptance: caption + poster → poster-only works, old approval becomes stale, empty campaign remains blocked, conflicting clear operations cannot overwrite a newer version.

### QA-05 — P2: After a save conflict, the old review still says “Current content” until reconciliation

1. Open the same campaign in two tabs at revision 6.
2. Save a new caption in A, creating revision 7.
3. Attempt to save different text in B.

B correctly rejects the save and preserves the draft, but its old review still shows `Current content`; correction and request controls also remain visually available before the user compares with the saved version. After comparison/reconciliation, the result correctly becomes stale. No successful stale mutation was demonstrated; this is a visible-state problem and server guards still apply.

Suggested work: as soon as a known 409 establishes a version conflict, mark review currency unknown/outdated and disable dependent mutation controls until reconciliation. See `frontend/src/LiveCaption.tsx:35` and the save catch handler.

Acceptance: after the 409, no result claims currentness and no correction, comment, finding decision or human request can proceed using the stale snapshot. Draft text stays intact.

### QA-06 — P2: Expired confirmed sources are presented as ready to check

1. Edit INR 699 with `Use until` 2026-10-31 in a campaign published 2026-11-12.
2. Save, then confirm it.

The source correctly stays expired for publication and is excluded from checks, but the success message says `Fact confirmed and ready to check.` The collapsed source card simply says `Confirmed`; its expiry is inside More details and actions. This can confuse source authority with applicability.

Suggested work: show `Confirmed · expired for publication` on the visible card and use validity-aware confirmation messaging. The engine’s exclusion behaviour should remain intact. See `frontend/src/LiveSources.tsx:156`.

### QA-07 — P3: Literal question marks in logo status copy

Visible strings include `Reference v2 ? Owner confirmed`, `Reference v2 ? manual owner verification required`, and `Saving brand logo?`. These appear in `frontend/src/BrandLogo.tsx:16` and `frontend/src/ReviewResults.tsx:20`.

Replace with intentional punctuation and plain status wording. This is a presentation defect, not a logo-matching failure.
